## 1. The three designs

### H1 (recommended): dual-resident weights, PP prefill on stage Models, one bulk reshard into the TP layout

Each card holds (a) its TP=2 rank Model exactly as `--tp 2` loads it (all 64 layers, half heads) and (b) a stage Model, both created and owned by that card's existing rank worker thread:
* X = layers [0,k] (as PP stage A today) with `stage_only` (no lm_head, no MTP, no drafter, no vision), state/KV allocated only for layers < k (item 11), embedding from the shared pinned host copy and a **borrowed** device mirror (item 12), KV sized for S tokens.
* Y = layers [k,64) + final norm + FULL lm_head + FULL MTP head, built as a **hole-prefix container** (item 6): `layers_` stays globally indexed, layers < k are default-empty `LayerWeights`, `NumLoadedLayers()` stays 64, DFlash target indices, `has_next_layer` and the `FinalLmHead` path are unchanged. No re-indexing anywhere.
The two Models of a card never run at the same time (the facade serialises commands). Each Model call runs inside a `Tp2TuningScope` that sets the thread's flag to the Model's own value (stage false, rank true) and restores it (section 7).

Prefill (rows >= `--pp-min-rows`, default 1024 in hybrid mode): the same ring, kernels and chunk grid as `PpModel::PipelinedPrefill`, re-hosted as two worker commands (section 7), except:
* the slot's KV payload disappears (Y's stage Model has no layers < k; saves 4.25 MiB of 24 MiB per chunk, ~0.28 ms per chunk on each side);
* Y's epilogue (MTP priming with the full head, final norm, full lm_head) is unchanged, so `Prefill()` returns logits byte-equal to `--pp 2` / TP=1;
* at the END of the call a reshard phase runs (section 3) and both TP rank Models adopt the post-prefill scalars (`Model::TpAdoptPrefill`); decode continues at TP=2.

Decode: untouched `TpModel` collective commands, MTP/DFlash included.

### H2: TP=2 prefill with PP-style chunk overlap (rejected, quantified)
TP=2 prefill per 256-row chunk: 8k TTFT 2.88 s / 32 chunks = 90 ms. The all-reduce share: 128 sites (2 x 64 layers) x 4 calls of 64 rows (mailbox holds 64 rows,
prefill.md 643) x 58.3 us (isolated 640 KiB, tp.md 1.3) = 29.9 ms = 33 % of the chunk; compute is ~60 ms. Even if ALL of it were hidden (needs a spin kernel running
concurrently with GEMMs on the same GPU, a two-chunks-in-flight wavefront through the per-layer GDN/KV dependencies, and a TDR-safe bound on the desktop card) TTFT_8k >= 60 ms x
32 = 1.92 s versus PP's 1.66 s; a realistic 50 % hiding gives ~2.4 s. At 32k+ the TP=2 rank's attention does not split (2 KV heads, tp.md 8.6) so TP=2 is 12.1 s vs PP 7.24 s and the best case
(-30 %) is ~8.5 s. H2 cannot reach PP's TTFT even in the ideal case, is the hardest to build, and gives up byte-identity with TP=1 prefill. Its one merit is zero VRAM duplication.

### H3: simpler variants (rejected)
* PP prefill + TP=1 decode with the DFlash/MTP drafter on the other card: the draft -> verify -> accept -> draft chain is serial, so moving the 5.8 ms drafter to X
  does not shorten the 33.6 ms round (it adds two cross-card hops, ~0.1-0.2 ms each); only draft-ahead-assuming-full-acceptance would hide it, and acceptance is ~4.1 tokens of 8.
  Best case 33.6 -> ~28 ms (1.2x) vs TP=2's 21.2 ms (1.58x). Plain decode gets nothing.
* Weight swap (keep one set of weights per card, reload the other layout from pinned host for each long prompt): 6.5-7 GiB at ~15-20 GB/s = 0.35-0.5 s each way per card plus
  warm-up; viable only as a VRAM fallback for 256k contexts, not as the default. (Recorded as H4, not planned. It is also the only option that removes the X squeeze of section 2.)
* Keep stage KV only during prefill (free/realloc around calls): saves 16 KiB/token/card but fights the allocator and `TpAllocGuard`; not in v1.
* A dedicated stage worker thread per card (4 threads, flag set once at load, no scopes): considered for item 2; rejected because it duplicates the rank worker's watchdog/poison/recovery plumbing for a second thread pair and still needs the same pinned-buffer relocation; the RAII scope + entry assertion is smaller and is required anyway as the guard.

## 4. Correctness definition (three gates, strongest first)

* **G-H1 byte identity at decode start, live state only (item 9).** Reference R: a TP=1 `Model` runs the same prefill; a host function `ReshardRef(full_state, r)` (CPU, built on the same RankRows tables) produces rank r's image of the LIVE state: KV rows [0,pos) of each attention layer and head slice, the live GDN recurrent slot and the 3 live conv entries per channel, MTP KV rows [0,pos), DFlash store window + `injected` count, the scalars.
  The comparison uses a NEW `Model::DebugLiveStateDigest()`, not `DebugStateDigest`: the latter hashes the whole recurrent buffer (all window slots and reserved slot 0) and the whole conv buffer including entries beyond the 3 live ones (TP rank pitch is 2+window) and `DebugZeroKvState` zeroes only KV and MTP KV (model.cpp:3294-3329), so it is valid only for cold-after-Reset scenarios and would fail spuriously on warm-turn and post-decode cases. `DebugLiveStateDigest` = per layer the live recurrent slot (`RecurrentSlotPtr(SlotForSeq(0))`, or window slot n-1 by the rule of `DebugLiveGdnDigest`, model.cpp:3348-3366) + the compact live conv entries (as `PpLiveDigest`, :378, through `CopyConvHistory`) + KV bytes of rows < pos only (full blocks + the partial block's rows, as `PpLiveDigest`) + MTP KV rows < pos + the DFlash window; digests are over canonical (layer, head, row) records so the host image and the device state hash identically. Gate: for both ranks, digest of the hybrid-prefilled TP rank == digest of the image loaded through a test-only `ImportFullState`. Scalars compared field by field.
  Equality is expected because stage prefill == TP=1 prefill (test_pp_real_identity, with the tuning scope of item 2) and the reshard is pure copy.
  **DFlash reference (item 10):** drafter outputs are not compared to a TP=1 Model, because the drafter's fc/k_proj/v_proj GEMMs run under the TP-thread tuning flag (linear.cpp:266-270). The reference for `dflash.k/v` is `InjectFeatures` run on a TP-thread (flag true) Model with the TP=1 run's captured features and rope rows, both as full injection (all rows) and as tail-only injection; the hybrid rank must equal both (this also proves the window-skip equivalence at s <= n-2048 and the 64-row slicing).
  **Negative controls (12; each must change an observable):** (1) swap the head halves, (2) drop a conv segment, (3) skip the MTP half, (4) skip the DFlash tail, (5) off-by-one block, (6) wrong rank mapping, (7) stale mirror, (8) skip scalars, (9) skip the TP -> Y MTP seed sync on a warm turn, (10) run the stage prefill with the TP2 tuning flag true (the stage digest must change on a rank-equal shape), (11) drop the image rope rows in the tail injection, (12) copy the MTP KV from block 0 instead of the primed range on a warm turn.
* **G-H2 decode equality.** 64+ greedy tokens (plain, `--mtp 3`, `--dflash 7`, one sampled seed) from TP=2 after the hybrid prefill == the same decode started from the resharded reference image (identical states and deterministic TP kernels => identical tokens, speculative accept stats, and first-token logits); shapes of test_pp_real_identity (1..8145 rows, prefix reuse 300+333 etc., warm turns, checkpoint save/restore, image rows) **plus**: an `--mtp 3` warm-turn case (turn 1 decoded at TP=2 with MTP, turn 2 hybrid-prefilled; the boundary priming of row p0-1 must use rank 0's seed), a DFlash warm-turn case, and a vision + DFlash case with an image straddling the 2048-row tail window.
* **G-H3 statistical.** KL(TP=1 || hybrid) teacher-forced on the kl_corpus (prefix prefilled by the hybrid path, continuation decoded at TP=2) <= 1.25 x the measured KL(TP=1 || TP=2) floor (0.00088-0.00089, docs/tp.md); top-1
  agreement within 0.3 pt of TP=2's. Not required: equality with `--tp 2`'s own text (different prefill numerics; the hybrid is strictly closer to TP=1).
* **G-T tuning-scope guard.** A test that fails if any Model entry point runs with `Tp2TuningForThisThread() != model.IsTpRank()` (section 7), plus the negative control (10) above.

## 5. Warm turns (decode modifies only the TP shards; the next pipelined prefill needs full-head state per stage)

`pp::MirrorTracker` generalises to a TP-master tracker: TP shards are the truth; each stage keeps `kv_valid_to` and `gdn_pos` (both only shrink on TP-only work: decode, spec rounds, restore, short TP prefill, Reset).
Before a pipelined call: (1) collapse speculative windows on the TP ranks (write-once: Materialize + ShiftConv; window slots: CollapseWindow); (2) **sync the scalars INCLUDING the MTP seed into BOTH stage Models**: `PpSetSyncState` today throws unless the Model is stage A (pp_stage_real.cpp:200-208) and copies only pos/started/mrope; it becomes `StageSetSyncState` for both roles and gains `mtp_seed_valid` + the 10 KiB `mtp_seed_hidden_` copied from rank 0 (without it Y's `mtp_seed_valid_` is stale after a decode, `have_boundary` at model.cpp:1447 is wrong and the row p0-1 of the resharded MTP KV is skipped or primed from a wrong hidden state); (3) gather: stage A <- rank 1's half local D2D + rank 0's half via host (27 GDN layers x 1.53 MiB = 41 MiB Y -> X), stage B <- rank 0 local + rank 1's half (21 layers, 32 MiB X -> Y), the two directions concurrent: ~3 ms transfer + ~4 ms fixed = **~7 ms** (today's sync-back: 6 ms for 76 MiB); (4) KV rows [kv_valid_to, p0): 8 KiB/row remote per direction, ~0.6 ms per 1000 generated rows, plus the local half; plus the single MTP KV block of section 3. After the call both sides are valid through the new end (the bulk reshard writes the TP shards for rows >= p0).
**Break-even (item 8, corrected).** The pipeline pays fill and drain: with ~51.8 ms per stage-chunk (1.657 s / 32; provisional, section 0) a call of c chunks costs ~(c+1) x 52 ms + ~45 ms of fixed tail (7 ms warm gather, reshard ~10 ms, DFlash tail ~30 ms), while `--tp 2` costs 90 ms per chunk (2.88 s / 32). Equal at 38c = 97 -> c = 2.55, i.e. **~650 rows**; at 512 rows (2 chunks) PP ~175-200 ms vs TP2 180 ms (no gain), at 768 about equal, clear gain from 1024 (~305 vs 360 ms). r1's "~50 rows" compared against the wrong baseline (it ignored fill/drain). **`--pp-min-rows` defaults to 1024 in hybrid mode** (it stays 512 for plain `--pp 2`, whose baseline is TP=1) until P3 measures a 512/768/1024/1536 sweep. Gather budget > 512 MiB of stale KV (~64k rows behind) falls back to the TP prefill path. `n_total > S` falls back too.
`SaveCheckpoint/RestoreCheckpoint` stay per-rank on the TP shards (unchanged); a restore invalidates `gdn_pos` and the stage seed. Prefix cache: unchanged (lives in the facade).

## 6. Speculative decoding
Already exists at TP=2 (MTP k<=7 with sharded head + replicated `mtp.fc`, DFlash2 replicated drafter + vocab-split target head with H6/H7 merges, sampled and greedy, G9/G10/G11 pass). The hybrid only has to deliver
their prefill-side state:
* **MTP:** KV primed on Y by the full head (the unchanged PP epilogue) then head-split to X over the primed block range (section 3); `mtp_seed_hidden_` replicated to both ranks at the end of the call, and, on a warm turn, TP rank 0's seed copied INTO Y before the call (section 5).
* **DFlash ring:** injected on both ranks from the last >= 2048 rows. The tail injection runs on the RANK threads (thread flag true) after the stage prefill has finished, i.e. outside `PrefillMultimodal`, whose `BlockGuard` has already cleared `mrope_block_` (model.cpp:1832-1839). So (a) the stage `PrefillMultimodal` is called with `rope_rows_out` (model.cpp:1841) and the temporal row of the tail window is shipped with the features to both ranks (`rope_t_host` of `InjectFeatures`, 64-row slices, `Model::TpInjectDflashTail(features, rows, start_pos, rope_t)`); text-only calls pass nullptr as `RunChunk` does; (b) the slicing is exactly 64 rows (a 256-row fc GEMM would differ numerically); (c) the start s is `max(p0, chunk-aligned n-2048)`; (d) the reference for the check is a TP-thread `InjectFeatures` run (section 4).
* TP=2 decode round stays ~21.2 ms (DFlash) / ~65 tok/s plain at short context (section 8 for longer contexts).

## 7. Threading, allocation, failure / recovery

**Who owns what (items 2, 3).**
* One rank worker per card owns BOTH the rank Model and the stage Model, and all pinned buffers the card produces into. Nothing allocates on the facade: the slot ring, the GDN hand/sync buffers, the reshard rings, the gather ring and the DFlash staging are created by `Run({rank}, ...)` commands at load (as the mailbox is, tp_model.cpp:424) and freed in `~TpModel` on the same threads; `kv_sync_` is allocated up front at its maximum (no lazy growth). `StageChannel` (host atomics) may live in the facade; its buffers may not be allocated there.
* `PpModel::PipelinedPrefill` today assumes B runs on the facade (pp_model.cpp:549-552, `PpImportGdnAsync`, `PpExportGdn` at :464, `PpExportKvRows` at :469 all execute on the facade after `BindStageB`). In the hybrid both stages are rank-thread commands, so P3 first refactors the orchestration into stage runners that take `(Model&, StageChannel&, plan)` and no thread assumption: `PpModel` keeps calling them (B on the facade, A on its worker; its tests are the regression guard), the hybrid posts them to both rank workers as one new command kind (no `TpComm`, so no spin kernels and no 500 ms bound). The "reuse PpModel/StageChannel state machines" claim of r1 therefore means: reuse the channel, the plan/tracker and the runner bodies, not the class.
* The pipelined prefill must NOT run inside a `TpCollectiveScope` (`tp_alloc_guard.hpp:27-34` counts allocations per thread; a lazy stage allocation would trip it); it is a plain command.

**Tuning scope (item 2).** `Model` gets `bool tp2_tuning_` (= is_tp_rank, set in `Load`) and every command that touches a Model goes through `RankSlot::With(Model&, fn)` = `Tp2TuningScope s(model.tp2_tuning_); fn(model);` where the scope saves the thread's current flag, sets the Model's, and restores on exit (also on throw). Models are only reachable through this wrapper (private members). `Model::Load` keeps its set-on-every-load behaviour (the cache key contains the flag, so toggling is safe) but is no longer relied on: after loading both Models on one thread the flag would follow the LAST load (stage load last -> TP decode silently on TP=1 tunings, slower and possibly outside the rank-shape legality rules; rank load last -> stage prefill GEMMs with rank-equal shapes such as 6144x5120 pick TP2 rows and the stage stops being byte-identical to TP=1). Guard: `Model::CheckTuningScope()` (throws `std::logic_error` if `Tp2TuningForThisThread() != tp2_tuning_`) at the entry of `RunChunk`, the decode steps, `VerifyWindow` and the drafter inject wrappers; test `test_tp_tuning_scope` + negative control (10). Part of P0.

**Destruction and borrowed state (item 12).** The stage Model's embedding device mirror is borrowed from the rank Model's `Container` through an `EmbedMirrorLease` that OWNS the device buffer (shared ownership: the uploading Container and every borrower hold a copy, the buffer is freed with the last), so no destruction order is required; each rank worker still destroys the stage Model first, then the rank Model, in the same command (`~TpModel` already resets the Model per rank thread), which returns the VRAM at that point. (The first P0 cut aborted in `~Container` on a live borrower; the review replaced that with ownership: a kept `ModelOptions` copy or a move-assigned `Container` could otherwise abort or free under a borrower.) Test: owner-destroyed-first read of the mirror (`test_stage_load`), lease ownership (`test_stage_load_cpu`) + load/destroy loop under the alloc guard.

**Failure.** Reuse `TpModel`'s state machine (kReady / kNeedsRecovery / kFatal) and `PpModel`'s channel poison. Any error on either card => `StageChannel::Poison`, join both workers (60 s no-progress watchdog = kFatal as today),
rethrow root cause, state kNeedsRecovery; `Reset()` = `TpGroup::Recover` + reset both stage Models + channels + tracker. Kill switch: `--hybrid off` / `R4DX_HYBRID=0` leaves `--tp 2` exactly as today (the hybrid is additive: `TpModel::Prefill`
dispatches to it only when rows >= min_rows, `n_total <= S`, and the mirror is feasible). Refusals as PP: rotated (quant2) containers, Gemma 4, probes, mismatched placement, split outside [1,N-1].
CLI: `--tp 2 --pp 2` (today mutually exclusive) selects the hybrid; `--pp-split`, `--pp-min-rows`, `--pp-devices` keep their meaning; new `--hybrid-ctx N|auto`, `--hybrid-reserve-gib X`.

2. Hole-prefix plumbing: smaller than r1's `layer_first` (no re-indexing; `NumLoadedLayers()` stays 64) but a hole that is executed silently uses null pointers: `Layer(i)` throws on a hole, the stage runners assert their [first,last) range is loaded. 8. Maintenance: another copy of the state-mapping logic; mitigated by deriving it from the loader's rule tables and the byte-identity gate on every change to a shard rule.
9. Pinned host RAM (~4.0 GiB here, ~8.6 GiB if the stage Containers kept private embedding copies) after the 2026-10-05 OOM power-cycle: shared copy mandatory, one big host job at a time.
10. The PP baseline itself is unverified in the corrected placement (stage A on the slower desktop card): G3 is defined against P-1, not against the old numbers.

## 12. P2 part 1 as built (2026-10-08): the reshard executor, the live-state hooks, the DFlash tail (branch hybrid)

Files: `reshard_exec.h` (HIP-free: `RectOf`, `OpSlice`, `SplitOp`, `PackCrossOps` -- the plan's copy ops as rectangles in a layer buffer and as row-aligned ring batches), `live_digest.h` / `live_state.h` (HIP-free: the canonical live-state digest, `LiveState` + the checksummed dump file), `dflash_tail_plan.h` (HIP-free: tail start on the call's 64-row grid, `TailCover`, `CheckTailInject`, `TemporalRopeRows`), `dflash_tail.h` + `hybrid_model.cpp` (`Model::Reshard*`, `StageArmDflashTail`, `TpInjectDflashTail`, the `R4DX_TP_TESTING` hooks `DebugLiveStateDigest` / `DebugExport|ImportLiveState` / `DebugExport|ImportFullState`), `MtpHead::KvCache()`.

* **Executor.** `Model::ReshardExport / ReshardImport(op, slice, side, host)` copy one row slice of a `hybrid::CopyOp` between the Model's layer buffer and a caller-owned pinned buffer; `Model::ReshardCopyLocal(stage, rank, op, slice, dir)` is the same-card D2D half. The address is `RectOf(op, slice, side)` and nothing else; the Model checks the holder (TP=1 / the op's stage for `kFull`, the op's rank for `kRank`), the buffer's row pitch against the plan's and the extent, and refuses GDN ops while a speculative window / pending write-once prefix has the live state off window 0 / offset 0 (`ReshardCollapse()`). Conv lines are staged through a device scratch that `ReshardInit()` allocates once (a missing scratch throws; nothing allocates in the hot path). Only enqueues on the Model's stream; the caller orders the two cards (`ReshardSync`).
* **Finding for P3 (fixed in the plan, `PlanParams::stage_b_conv_pitch`).** Stage B carries the MTP head, so it is loaded with `mtp_draft_k > 0` and its conv lines are `conv_width - 2 + window` entries, like a speculating rank's, while stage A's are 3. `PlanParams::ForSplit` assumed 3 for both; the executor's pitch check would have refused it. P3 sets `p.stage_conv_pitch = x.ReshardConvPitch()`, `p.stage_b_conv_pitch = y.ReshardConvPitch()`, `p.rank_conv_pitch = rank.ReshardConvPitch()`. (Its recurrent allocation is also `window` slots per layer unless write-once is on -- a P3 memory item, not touched here.)
* **Digest.** `Model::DebugLiveStateDigest()` = `pos`, per attention layer KV rows < pos (head-major records through `KvDigester`), the MTP head's rows < pos - 1 (row pos - 1 is primed by the NEXT call), per GDN layer the live recurrent slot and the 3 live conv entries (window slot / offset of a speculative round followed), the drafter's visible window `[max(valid_from, injected - 2048), injected)` + frontier. `hybrid::DigestLiveImage` hashes a host image identically (CPU test: a device-shaped holder with garbage past the rows, stale slots and long conv lines digests like its image, for the full holder and each rank).
* **DFlash tail.** The ring is replicated and fed the last >= 2048 rows from host features in 64-row slices (`InjectFeatureRowsFromHost`, the loop `Model::TpInjectDflashTail` runs, after the checks of `CheckTailInject`); the start `s = DflashTailStart(p0, n)` is on the call's own grid `p0 + 64 j`, so every slice has the (start, rows) it has in a full run. The stage side is `StageArmDflashTail(host, cap, s, n)` before the call / `StageDisarmDflashTail()` after: it takes the capture-observer slot, so it needs a Model whose prefill drains its chunks -- stage B (its slot carries stage A's columns, so Y sees all five), a monolithic Model, PP-emulate; stage A never drains. The rope rows come from `PrefillMultimodal(..., rope_rows_out)` ([3, n - p0]) through `TemporalRopeRows`.
* **Not done here (P3 / later):** the orchestration (ring pipelining of D2H/H2D across the two rank threads, events between cards), `TpModel` plumbing, DFlash tail wired into a hybrid prefill call, Gate B (full depth) and the real-container identity.
