Notes: The decode path of the engine streams every weight of the model once per generated token, so the time per token is set almost entirely by how fast the weights can be read from video memory. The card has a nominal bandwidth of about 640 gigabytes per second, but a single linear layer rarely sustains more than eighty to ninety percent of it, because each kernel launch has a ramp at the start and a tail at the end where only a few workgroups are still running. The team measured that the tail costs between two and six microseconds per launch, which is small for the large projections but significant for the small key and value projections that finish in under ten microseconds. A second concern is the shader clock. Under a sustained load the card is limited by its power budget, and a kernel that spends more of its time on arithmetic draws more power, so the clock can fall by several percent while the memory clock stays fixed. A format that trades memory traffic for arithmetic can therefore look faster in a short isolated benchmark, where the clock stays near its boost value, and slower in the real model, where the whole step runs back to back for minutes. A third concern is the cache. The last-level cache holds sixty-four megabytes, which is enough to keep the activations and some small weights resident between layers, and a benchmark that replays the same layer many times can see cache hits that the real model never gets. The notes recommend measuring the clock inside the real model, timing each class of linear layer in place, and comparing both against the isolated benchmark before drawing any conclusion about the format.
